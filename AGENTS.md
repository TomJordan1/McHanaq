## Reglas rápidas para agentes

* **Estructura oficial unificada:** todo el código fuente vive bajo `src/` (`src/frontend/`, `src/backend/`, `src/analytics/`, `src/gee/`). Las carpetas raíz son `contracts/`, `data/`, `docs/`, `presentation/`, `src/`, `tests/`.
* **Rutas relativas en backend:** `src/backend/app/main.py` usa `ROOT = Path(__file__).resolve().parents[3]`.
* **Ownership actual (Fase A):** Tom es responsable de `src/analytics/` y `src/backend/`; Angelo de `src/gee/` (datos en `data/intermediate/` y `data/processed/territories.geojson`); Sebastian de `src/frontend/`; Jean Pierrer de `contracts/`, `data/fixtures/`, `data/reference/`, `docs/`, `tests/acceptance/` y `presentation/`.
* **Almacenamiento e infraestructura (Microsoft Azure Free Tier + Cloudflare Pages):** Las tareas batch en GEE exportan inicialmente a Google Drive o GCS desde Earth Engine Code Editor; luego se descargan a `data/intermediate/` y se espejan en **Azure Blob Storage (Free Tier / Azure Storage)** junto con los paquetes procesados de `data/processed/`, sincronizándose offline o en build/deploy hacia `data/processed/`. El despliegue oficial (`infra/azure/`) corre en **Azure App Service (Plan Free F1, Linux Python 3.11)** usando el `requirements.txt` raíz, `infra/azure/startup.sh`, `GET /` para warm-up y `MCHANAQ_CORS_ORIGIN_REGEX` para vistas previas, leyendo únicamente `data/processed/` o `data/fixtures/` (nunca consulta GEE ni almacenamiento externo por petición HTTP salvo la excepción explícita de Fase 2 descrita abajo). El frontend (`src/frontend/dist/`) se publica en **Cloudflare Pages** (`src/frontend/public/_headers`, recomendado) o **Azure Static Web Apps (`infra/azure/staticwebapp.config.json`)** con `VITE_API_BASE` / `VITE_API_BASE_URL` apuntando a Azure App Service (`render.yaml` queda únicamente como referencia *legacy*/opcional).
* **Estado actual de datos (`data/processed/`):** `data/processed/territories.geojson` (24 polígonos de Ucayali: 4 provincias + 20 cuencas ANA nivel 4), `ucayali_territories.geojson`, `ucayali_districts_static.csv` y los artefactos precalculados de Fase 2 (`spread_forecasts.json` y `spread_outputs/`: GIF, MP4, Shapefiles QGIS `.zip` e infografías PNG de 48 h) ya están generados; los JSON de series de Fase 1 (`metadata.json`, `activity_daily.json`, `activity_summary.json`, `sensor_comparison.json`, `conditions_assessment.json`) esperan la descarga de los CSVs de GEE en `data/intermediate/` para ejecutarse con `python -m src.analytics.run_pipeline` (mientras tanto, desarrollo y QA operan con `data/fixtures/`).
* **Mapas base libres (sin API keys):** usar OpenTopoMap (hidrología/relieve), OpenStreetMap (con filtro CSS para modo oscuro) y Esri World Imagery. No usar teselas de CARTO que exigen API key.
* **Ventana común Ucayali y días útiles:** la ventana multisensor verificada en GEE (`MODIS_TERRA` + `MODIS_AQUA` + `VIIRS_SNPP` + `ERA5-Land`) abarca **`2012-01-19` a `2026-11-02`** (último mes completo común **`2026-10`**, ~14.8 años > mínimo de 5 años), usando `COPERNICUS_DEM_GLO30` (las exportaciones `2000–2011` quedan retiradas como nota *legacy* fuera de alcance operativo). `available_date_ranges_by_sensor` y `available_periods_by_sensor` exponen únicamente días útiles registrados (`valid_land_pixels > 0`, nubosidad `< 30 %` / `observation_coverage >= 0.70`, `activity_rate` no nulo).
* **Integridad científica:** API diaria por defecto (`date=YYYY-MM-DD`, `from`/`to`); nunca sumar conteos entre sensores (`MODIS_TERRA`, `MODIS_AQUA`, `VIIRS_SNPP`); `null` nunca es `0`; susceptibilidad contextual no es predicción de ignición ni propagación; Fase 2 (`spread_model`) es estrictamente opcional y desacoplada de Fase 1.
* **Excepción de tiempo real (Fase 2, opcional):** `/api/v1/realtime/area` y `/api/v1/spread-simulate?use_open_meteo=true` consultan Open-Meteo y NASA FIRMS por petición HTTP — están **apagados por defecto** y solo se activan a propósito con `MCHANAQ_ENABLE_REALTIME=1`. Sin esa variable, responden con datos vacíos/estado `disabled` en vez de llamar a servicios externos, para no violar la regla de solo-lectura de `data/processed/`/`data/fixtures/` salvo que el equipo decida explícitamente usarlo (ej. demo en vivo).
* **Dependencias de Fase 2:** `httpx` (obligatorio: se importa a nivel de módulo en `main.py`, su ausencia tumba TODO el backend, no solo Fase 2) y `shapely`/`numpy`/`geopandas` (diferidos, solo rompen los endpoints de `spread_model` si faltan) deben estar en `requirements.txt`. `geopandas` depende de GDAL — probar el build en Azure App Service Free F1 antes de confiar en que compila ahí.
